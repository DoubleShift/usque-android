# usque-android App 重设计方案：连接策略引擎 + 界面重构

> 目标：把 §usque 的全部抗封锁能力装进 App，让用户"一键获得当前网络下最优的上网体验"（抗干扰优先，速度其次）。
> 前置阅读：`_docs/research/usque-features.md`（能力与机制）。
> 设计原则：**用户不需要懂协议——App 是自动挡，手册模式只是后备**。延续本项目的内存纪律：不引入 Compose/Material，仍用轻量 View + 自绘风格。

---

## 1. 核心架构：连接策略引擎（Connection Strategy Engine）

现状：用户手动选协议、填端点、填 SNI——对不懂 MASQUE/WG 的用户等于黑盒。
重设计：Go 层新增 `internal/strategy` 包，把三个杠杆变成**自动决策**。

### 1.1 探测套件（Probe Suite）

网络变化时（或用户手动触发）运行一次，全部复用 `internal/scanner` 现有探针：

| 步骤 | 内容 | 复用 | 耗时 |
|---|---|---|---|
| P0 | 基础连通（api.cloudflareclient.com 可达性） | 新增（HTTPS GET） | ~1s |
| P1 | MASQUE QUIC 握手：7 端口 × SNI 候选集 | scanner 的 masque 探测逻辑（需从 warpscout masque.go 移植握手探测） | ~10s |
| P2 | WG 握手：主端口 4 个 + 若 P1/P2 全灭再扫备用 50 端口（每 /24 采样 2-4 地址） | scanner/wgtunnel handshake（已有） | ~15-40s |
| P3 | 对通过者做**隧道内验证**：meta 拉取（出口 colo）+ 短 durability ping（5 发，判 DPI 断流） | scanner tunnelProbe（已有） | 与 P2 并行 |
| P4 | 速度粗测：对最优 2-3 个候选各拉 3s 下载量（speed.cloudflare.com/__down） | warpscout speedTest 移植（可选，默认关） | ~10s |

产出：一个**候选列表**，每项 = {协议, 端点, 端口, SNI, RTT, 出口colo, 是否断流}，按 (可用, 未断流, 丢包, RTT) 排序。

### 1.2 决策与降级阶梯（Fallback Ladder）

按"抗干扰优先、速度其次"排序默认阶梯（可调）：

```
1. MASQUE/QUIC + 最优(端口,SNI)   —— 伪装最好，anycast 延迟天然最低
2. WG + 扫描出的最优端点          —— 通常最快、可挑出口，但怕 DPI
3. WG + 备用端口扫荡结果          —— 主端口被封时
4. (Phase C) masque-h2/TCP        —— UDP 整体被封时
5. (Phase C) l4-socks 模式        —— 极端环境的轻量兜底
```

决策规则：阶梯上第一个"通过验证 + RTT < 阈值(如 400ms)"的策略胜出；若 MASQUE 可用但 WG 实测快 >30%，用户可在设置里选"速度优先"让 WG 升位。

### 1.3 网络画像（Network Profiles）

按 WiFi SSID / 移动网络 MCC+MNC 存档每个网络的：
- 胜出策略 + 完整候选列表 + 验证时间戳
- 已知被封锁的组合（黑名单，下次跳过）

切换网络 → 命中画像 → **秒连**（不重探）；画像超过 N 天未验证 → 后台轻量复探一次。这是"切网不断线"体验的关键。

### 1.4 运行时健康监控与自动切换

- WG：复用 api/wgtunnel.go 的看门狗（握手新鲜度）。
- MASQUE：QUIC 连接状态 + MaintainTunnel 的重连事件。
- 触发降级：连续 2 次重连失败或持续 stale → 自动切到阶梯下一级，通知栏提示"已切换到 XX"。
- 用户无感，日志留痕（现有 tunnel.log 机制）。

## 2. 界面重构（保持轻量 View，不引入 Compose/Material）

本项目的核心纪律是低内存（曾为省 2-3MB 移除 Material/AppCompat），界面重构走**同一套 View + 新视觉语言**，不换框架。

### 2.1 主屏（Connect 页）——从"一个按钮"变成"状态仪表盘"

```
┌──────────────────────────────┐
│ RE.usque            [⚙ 设置] │
│                              │
│      ╭──────────────╮        │
│      │   ● 已连接    │        │  ← 保留大圆钮，环色=状态
│      │   42 分钟     │        │     绿=连接/黄=协商/红=断
│      ╰──────────────╯        │
│                              │
│ ┌─ 当前连接 ────────────────┐ │
│ │ WireGuard · 188.114.98.96 │ │
│ │ 出口 🇺🇸 LAX 洛杉矶 · 173ms│ │  ← colo+国旗来自 meta 查询
│ │ 自动模式 · 家庭WiFi 画像   │ │
│ └───────────────────────────┘ │
│ ┌─ 网络 ────────────────────┐ │
│ │ 家庭WiFi   WG·LAX·173ms ✓ │ │  ← 画像列表，点开=详情/重测
│ │ 移动网络   MASQUE·443 ✓    │ │
│ └───────────────────────────┘ │
│ ┌─ 扫描与工具            ›  ┐ │
│ ┌─ 分应用代理            ›  ┐ │
└──────────────────────────────┘
```

关键点：把"现在用的什么、为什么、出口在哪、多快"全部亮出来——这是用户建立信任的核心，也是对我们已有能力的可视化（meta 查询一行代码的事）。

### 2.2 扫描页升级

- 顶部三个模式：**快速探测**（策略引擎的 P0-P3，默认）、**深度扫描**（现有全量端点池）、**SNI 测试**（移植 warpscout findsni：枚举候选 SNI 找当前网络放行的）。
- 结果行增加出口 colo 排序/筛选；"应用到当前网络画像"而不是全局覆盖。
- 扫描历史保留（每网络一份）。

### 2.3 设置页

- 连接模式：自动（默认）/ 手动。手动展开 = 现有的协议/SNI/端点三项（保留，作为专家模式）。
- 策略偏好：抗干扰优先（默认）/ 速度优先（WG 升位）。
- 自动降级开关 + 通知。
- 保留现有：SNI、端点、分应用、日志路径。

### 2.4 视觉

暗色为主（VPN 用户偏好 + OLED 省电），主色沿用现有的绿系；卡片层级用深浅两档灰；状态色（绿/黄/红）贯穿连接钮和列表徽标。全部仍用 shape XML + 主题覆盖，零新依赖。

## 4. 阶段划分

- **Phase A（本次核心）**：internal/strategy 探测+决策+画像；主屏仪表盘 + 网络列表重构；扫描页三模式；自动降级。→ 交付"一键最优连接"。
- **Phase B**：视觉打磨（暗色主题统一、动效）、扫描历史、统计（按网络的连接成功率/延迟趋势）。
- **Phase C**：上游能力移植（h2 → l4 → account），补齐降级阶梯的后两级。

依赖风险：P1 的 MASQUE 端口探测需要从 warpscout masque.go 移植握手验证到本地 scanner（目前 scanner 只有 WG）——工作量中等，是 Phase A 唯一的新协议代码。

---

## 5. 明确不做的

- 不引入 Compose/Material（内存纪律优先）。
- 不做 Root 模式、不做第三方订阅协议（shadowsocks 等）——定位就是 WARP 客户端。
- 不做自动分享/测速排行——隐私面。
